# 安全模型

## 威胁假设

用户任务、仓库代码、README、测试输出、持久会话和模型回复都视为不可信输入。Docker 不是前提，
所以应用层权限控制必须独立成立。

## 已覆盖边界

规划/编码/审查扩展的具体权限和恢复边界见 [多模型工作流](WORKFLOW_PIPELINE.md)：
规划/审查在工具 Schema 和完整回复两层限制只读，JSON 产物无授权权力。审查批准需要真实的
本轮改动文件完整读取，且不能覆盖外层宿主验收。审批仍只控制具体副作用；审查失败不回滚
此前获批写入，文件读取证据不构成跨进程文件锁。阶段私有推理不写入公共会话或审计产物。

- **目录边界**：路径解析后必须仍位于工作区；拒绝 `..`、外部绝对路径和符号链接逃逸。
- **敏感文件**：默认拒绝 `.env`、Git 内部目录和常见凭据文件。
- **写入审批**：只读工具可自动执行；创建、替换和全量校验后一次写回的多段补丁都需要明确批准。
  写入显示有界、脱敏 unified diff；命令显示完整 argv 与 cwd。
- **三态审批**：允许一次、本会话允许同类或拒绝；非 TTY 默认拒绝，硬 DENY 不可被批准覆盖。
- **精确授权与 TOCTOU**：写入 scope 绑定完整参数和已审阅文件的 preimage 哈希，命令 scope
  绑定完整 argv/cwd；目标版本变化后不会复用本会话批准，预览后再变化也会由哈希复核拒绝。
- **命令边界**：只接收 argv 数组且 `shell=False`；可执行程序必须在白名单中。
- **uv Coding Profile**：只允许受限的 sync/lock check、pytest、Ruff check/format check、
  unittest 和 compileall 形态；仍需批准。`uv add`、任意 Python、Ruff 修复参数和路径逃逸拒绝。
- **资源限制**：命令有超时；文件读取、搜索结果、单条 trace 事件、replay 总量和
  OpenAI-compatible HTTP 响应体都有上限。
- **会话限制**：原始 journal 和活动 checkpoint 有事件数/字节上限，checkpoint 与恢复尾部共用
  字节预算；会话按工作区隔离并校验 Session ID，跨进程提交使用文件锁与序号冲突检查；Base URL
  元数据拒绝凭据、query 和 fragment。
- **本机权限与耐久写入**：会话目录和文件显式设置为 `0700`、`0600`。会话 append/状态和工具
  文件写入使用 `fsync`；替换走同目录临时文件 + `os.replace`，新建走硬链接独占创建。
- **运行时身份**：Provider 元数据可恢复但不保存 key；REPL `/resume` 不会静默跨
  Provider、模型或 Base URL 切换，而是给出显式重启命令。
- **凭据脱敏**：trace 对 API key、token、password、authorization 等字段递归脱敏。
- **完成证据门**：成功写入后缺少成功验证 ToolResult 时拒绝 `completed`，但它不是业务语义证明，
  也不能替代 Sandbox。
- **原始历史保留**：压缩只写活动窗口，不覆盖 append-only 原始消息，便于审计压缩前事实。
- **中断恢复**：journal 使用递增 `seq` 并按阈值分段；checkpoint 保存 `through_seq`。恢复重放
  checkpoint 后的尾记录，忽略最后半行，对缺失 ToolResult 补 synthetic failed 结果且不重放工具。
- **循环熔断**：达到最大步骤后停止，避免模型无限调用工具。
- **流完整性**：工具参数分片只有在正常结束、JSON 完整且 finish_reason 匹配后才形成调用；
  任何部分流中断都不会执行半条工具，也不会自动重放已发出分片的请求。
- **可信 Hook 边界**：Hook 由宿主显式注册且收到数据副本；before_tool 可以额外拒绝，不能授予
  Policy/Approval 已拒绝的权限。Hook 异常默认拒绝对应工具。
- **用量账本**：服务端 usage 以 run_id 幂等写入会话目录，沿用本机文件锁、原子替换、字节和
  事件数上限；账本文件权限为 `0600`。
- **配置边界**：`.env` 只在启动目录或显式指定路径读取，TOML 由 `--config` 加载；不执行
  shell 展开或第三方配置脚本，密钥不写入 profile 元数据。模型仍不能通过工具读取 `.env`。
  共享 `[connection]` 是显式复用同一服务的地址和 Key；profile 换服务必须同时覆盖
  `base_url` 和 `api_key_env`，不允许只换地址并隐式继承共享密钥。缺失独立 Key 不回退共享 Key。
- **路由边界**：分类阶段只收当前任务，无工具权限，只接受 simple/complex 两种标签；
  拒绝额外字段、重复字段和工具候选，失败保守转主力，原文不加入正式历史。
  分类不是权限判断器；自动模式的 economy 执行请求只暴露只读 Schema，并复核完整回复中的工具名。
  副作用候选先丢弃并升级主力；主力的调用仍经 Policy/Approval。固定 profile 使用常规审批。

自动路由会把活动上下文发送给 economy/primary 所选模型；共享连接时是同一端点，独立连接
时可能是不同供应商。启用前应使用可信服务，Key 相同不意味着各模型的数据处理策略相同。
轻量分类只接收本次任务，不包含文件与完整历史；分类失败事件使用固定原因，避免回显服务错误。
若独立连接分别配置不同供应商，分类失败转主力可能把本次任务交另一服务，执行则接收活动上下文。
`/model` 切换 profile 会新建会话，旧对话不会由此自动迁移。默认不要求价格，历史显式金额预算
也不是供应商硬扣费限额；细节见 [配置与模型路由](CONFIGURATION_AND_ROUTING.md)。

## 首版刻意禁止

- `sudo`、`curl`、`wget` 和任意包变更命令。
- `git push`、`git reset`、`git clean` 等外部或破坏性 Git 操作。
- shell 管道、重定向、命令替换以及 `shell=True`。
- 默认网络访问。
- Agent 自主扩大工作区或关闭审计。

## 审批不等于 Sandbox

允许一次或本会话允许同类，只表示用户接受了通过 Policy 语法检查的具体 scope。它不是操作系统
隔离，也不证明仓库代码可信。`--yes` 仅适合可信测试工作区，并且仍不能绕过路径、敏感文件和
危险命令硬拒绝。

获批的 `uv sync --locked/--frozen` 可能访问包索引或下载缺失依赖，获批的 pytest/unittest 会
执行仓库代码。需要严格断网或运行不可信代码时，应使用由用户准备的容器/虚拟机和独立网络策略。

审批预览有长度上限，脱敏也只能降低常见凭据误显风险，不能证明任意文本都不敏感。TOCTOU
哈希复核能发现审批后目标内容改变，但不能隔离同机恶意进程或替代操作系统权限边界。

## 耐久写入与恢复不等于事务

`fsync`、同目录临时文件、`os.replace` 和独占新建能减少半写与意外覆盖。journal 最后一条半行
可忽略，checkpoint 后的完整尾记录可重放。但这不是跨多个文件的 ACID 事务，也不承诺所有
文件系统、磁盘缓存或突然断电场景都零丢失。

synthetic failed ToolResult 只表示“恢复时没有可信的已落盘结果，而且工具没有被自动重放”。
它不能证明中断前工具绝对没有执行过；涉及副作用时，用户必须先检查目标文件、命令结果和 trace。

## Provider 输入边界不等于网络隔离

OpenAI-compatible 响应体上限防止单个成功或错误响应无界占用内存。Session 中的 Base URL 要求
HTTP(S) 主机地址，并拒绝用户名、密码、query 和 fragment，以免把明显凭据写入元数据。它们
不验证第三方服务可信度，也不阻止已获准的 Provider 网络请求。

## 尚未声称解决的问题

本项目不是生产级操作系统 Sandbox。即使命令有白名单，解释器本身也可能执行任意代码；因此
真实、不可信仓库的高风险执行仍应放入由用户准备的容器或虚拟机。首版重点是展示“默认拒绝、
最小授权、证据留存”的应用层设计，而不是宣称绝对隔离。

## 发现问题时

请不要提交包含真实凭据、私有仓库内容或可直接利用细节的公开 issue。先保留最小复现、trace
中的事件类型和本地版本信息，并确保所有 secret 已删除。
