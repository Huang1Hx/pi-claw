# 评测任务集说明：名称、代表性与选取理由

本页集中说明项目用到的**三套任务集**：它们各自的定位不同，不能互相替代，也不叠加成一个“总分”。

| 任务集 | 定位 | 规模 | 是否对外公开 | 代码/产物位置 |
| --- | --- | --- | --- | --- |
| 自建确定性回归（90-trial） | 内部多模式对照 | 10 任务 × 3 模式 × 3 次 = 90 | 否（自建） | `src/evaluation/mode_task_catalog.py` |
| SWE-bench Verified 子集 | 外生公开集对照 | 500 → 筛 41 → 健康 37 | 是（公开数据集） | `runs/swebench-verified/`（gitignore） |
| 锚 off/on 精简对照 | 机制对照（本次） | 2 任务 × 2 臂 × 2 后端 × 2 次 = 16 | 否（自建） | `scripts/eval_anchor_compare.py` |

---

## 1. 自建确定性回归集（90-trial）

**目的**：在同一确定性协议下，对照 `single / workflow / team` 三种执行模式，并守住阶段 3 的安全与生命周期硬门槛。

**组成**：`10 任务 × 3 模式 × 3 次 = 90 trial`（`ITERATION_038`）。

| task_id | 语义 |
| --- | --- |
| `inventory_reservation` | 批量库存原子预留逻辑 |
| `window_merge` | 带容差的时间窗口合并逻辑 |
| `permission_filter` | 角色权限请求过滤逻辑 |
| `balance_transfer` | 账户批量转账原子处理逻辑 |
| `dependency_order` | 稳定依赖拓扑排序逻辑 |
| `event_deduplication` | 有序事件去重与冲突检测逻辑 |
| `rate_limit_window` | 滑动窗口限流判定逻辑 |
| `config_overlay` | 受保护配置覆盖逻辑 |
| `worker_assignment` | 最小负载工作节点分配逻辑 |
| `versioned_update` | 乐观锁版本批量更新逻辑 |

**代表性**

- 覆盖后端高频的“纯函数 + 边界 + 顺序/原子/并发语义”模式：排序、去重、限流、权限过滤、乐观锁。
- 每个任务都预置了**隐藏用例可检出的缺陷**（fail_to_pass）；公开测试只覆盖基本路径，隐藏用例覆盖边界、类型与原子性。
- 因此测的是“能否按证据修好、且不越权、不回归”，而不是记忆或模型常识。

**为什么选这些任务**

- 确定性、无网络、结果可复现，适合跨模式对照。
- 参考实现限定在受限纯函数语法（无导入/递归/推导式），便于做确定性的安全与生命周期门槛。
- 任务、隐藏用例与阈值在**实现冻结后不再修改**；不因分数调整题目。

**口径与结果**：grader `agent-modes-2.2`、模型 `deepseek-flash`、`max_steps=24`、`deadline=420s`、`workers=3`。
同协议回归最终 **90/90**（single 30/30、workflow 30/30、team 30/30）。

**另有 holdout（不计入 90 口径）**：`merge_sorted_streams`（合并有序流并校验非递减）、
`run_length_encode`（相邻游程编码）、`rolling_max`（窗口最大值）；`3 任务 × 3 模式 × 3 次 = 27`，
实现冻结后一次性加入，**27/27**（`ITERATION_039`）。holdout 只证明新任务上的泛化，不等于通用能力。

**局限**：任务为自建、规模有限，只能说明“在受限语法与固定协议下的稳定性”，不能外推为开放世界能力。

## 2. SWE-bench Verified 子集（外生公开集）

**目的**：用一个**公开数据集**做外生对照，避免“自己出题自证”。

**筛选**：从全量 500 条按“纯 Python、依赖轻、测试快、gold 补丁小、FAIL_TO_PASS ≤ 8”筛选，
按仓库分层取样得 41 条（`external_eval/selection.json`），其中环境健康 **37 条**。

| 仓库 | 健康条数 | 实例 |
| --- | --- | --- |
| psf/requests | 4 | `psf__requests-1142`、`-2931`、`-5414`、`-6028` |
| pallets/flask | 1 | `pallets__flask-5014` |
| pylint-dev/pylint | 6 | `-4661`、`-4970`、`-6386`、`-6903`、`-7080`、`-7277` |
| pytest-dev/pytest | 11 | `-5262`、`-5809`、`-6197`、`-6202`、`-7236`、`-7432`、`-7571`、`-7982`、`-8399`、`-10051`、`-10081` |
| sphinx-doc/sphinx | 15 | `-7440`、`-7889`、`-7910`、`-8269`、`-8459`、`-8475`、`-8595`、`-8638`、`-9230`、`-9258`、`-9591`、`-9673`、`-9698`、`-10323`、`-10466` |

**为什么选这些**

- 覆盖真实开源仓库（工具库、Web 框架、静态检查、测试框架、文档工具），比自建任务更接近真实缺陷。
- 筛选条件保证在本地固定镜像内可复现、判定期可 `--network none`。
- 排除 `requests` 另 4 条 2013 年旧例：依赖实时 `httpbin.org`，与离线判定冲突。

**隔离**：代码在独立 `external_eval/`，**不导入也不修改**冻结评测入口；产物只写 `runs/swebench-verified/`（gitignore）；
不进入主 `pytest`/CI；外部实例 id 与冻结任务 id 断言无重叠；只跑单一模式（`workflow.coder`）。

**口径**：主口径 `relative_resolved = ftp_all_passed && 无相对 gold 的新增 PASS_TO_PASS 回归`；
官方 `resolved` 受本机环境噪声影响，作参考。

**结果**：首轮 relative **20/37（54.1%）** → 坏例自修复后 **37/37**；官方口径 24/37；
把 `loop_detected` 结论回灌产品侧后首轮升至 **78.4%**（`ITERATION_040`）。

**局限**：受限于本地镜像与仓库依赖，只覆盖 Python 生态的 5 个仓库；官方口径低于 relative 口径，两者不可混用。

## 3. 锚 off/on 精简对照（两个经典任务）

**目的**：为“任务锚是否影响执行”提供**真实模型**的直接对照（`M7b`）。

**任务**（`scripts/eval_anchor_compare.py`）

| task | 初始内容 | 任务/目标 | 约束（pin） |
| --- | --- | --- | --- |
| `fizz` | `fizz.py` 对 15 倍数返回错误，`test_fizz.py` 失败 | 修 bug 使测试通过 | 不得改 `test_fizz.py`；只做最小改动 |
| `stats` | `stats.py` 只有 `mean`，`test_stats.py` 引用 `median/variance` | 实现 `median`/`variance` 使测试通过 | 不得改测试；空列表须抛 `ValueError`；非空 `mean` 行为保持 |

**代表性**

- 经典“读代码 → 定位 → 最小修改 → 跑测试 → 复验”的多步编码回路。
- `stats` 额外加入**约束遵守**（错误契约 + API 行为），正是 pins/任务锚要保护的场景。

**为什么选这两个**

- 需要 goal/pins 有实际内容，锚才有可注入的东西。
- 有**客观成功判据**：任务自带 `unittest`，由宿主复算；约束可由“测试文件 hash 不变 + `mean` 行为”检验。
- 任务短、成本可控，适合作为精简对照而非全量评测。

**协议与结果**：`deepseek-flash`，2 任务 × off/on × files/sqlite × 2 次 = **16 次运行**；全部通过、约束零违反。
锚的 Token 开销约 **+1.5%（files）/ +2.9%（sqlite）**；**off/on 行为无差异**，故**不宣称**降低漂移或提升成功率。

**局限**：单回合短任务，**未覆盖**长会话多次压缩/重启/提示注入等长程漂移场景；“防漂移收益”仍未测。

## 如何解读这三套结果

- 三套任务**定位不同、不可相加**：90-trial 看内部模式对照与安全门槛，SWE-bench 看外生公开集，fizz/stats 看锚机制。
- 报告只宣称**已证实**的部分：机制（约束保留、版本、恢复）可复核；模型级收益（降漂移/提成功率）除非有对照证据，否则不声明。
- 任何新任务集都应先冻结任务与判据、再运行；不得按结果改题或删失败。
