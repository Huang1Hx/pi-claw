# Iteration 042：默认交互可靠性

## 基线与目标

本轮针对真实用户在默认交互中遇到的四类失败：纯问答被提示词引导成仓库任务，常见诊断命令
被策略拒绝，流式响应在读取超时后无法从未完成候选恢复，以及无效写入预览仍触发审批。
目标是修复这些行为，同时维持工作区路径、审批和工具副作用边界。

## 范围与修改

| 部分 | 修改与取舍 |
|---|---|
| `src/core/prompts.py` | 区分纯问答与依赖工作区的任务；仅后者需要先检查文件，创建项目限于相关路径。提示词不替代宿主验收。 |
| `src/security/policy.py` | 在 `coding` profile 中精确放行版本查询、受限 pytest 入口和 Node 语法检查；仍需审批并做路径校验，不放行任意脚本执行。 |
| `src/providers/streaming.py`、`src/providers/openai_compatible.py`、`src/interfaces/rendering.py`、`src/interfaces/repl.py` | 暂时性 HTTP/读取错误及 SSE 传输截断发生在完整消息前时，作废已展示的未完成候选并有界重试模型请求；无效 JSON/SSE 不重试。保留此前已完成的编码候选；完整消息和工具副作用绝不重放。Kimi 的单次尝试配置不变。 |
| `src/tools/preview.py`、`src/tools/executor.py` | 写入预览无效时在审批前拒绝，提供具体原因；不存在或不唯一的目标、最终写入内容超限均不能进入审批流程。 |
| `tests/test_live_interactive.py` | 新增显式启用的真实模型端到端冒烟：默认流式配置、纯问答、`/status`、`/usage`、`/exit`、无多余工具调用。普通 CI 不调用模型。 |

离线测试同步覆盖上述正向和拒绝场景，原有断言中依赖旧行为的三处已调整。README 与运行时、
安全、路由、工作流和评测文档同步更新为新重试语义；历史评测数字不重算。

## 验收标准

- 纯问答不触发仓库工具；工作区任务仍可正常使用工具。
- 新允许的诊断命令只在受限参数和路径下通过；任意执行、越界路径继续拒绝。
- 未完成流式消息发生暂时性传输失败时，候选明确作废且最多按配置重试；不会执行半条工具，
  也不会重放已完成消息或工具副作用。
- 无效预览零次审批、零次写入；包括替换后总字节数超限和多段编辑的中途超限。
  有效预览仍受版本绑定和原有审批约束。
- 完整离线测试、Ruff、格式检查、构建、敏感信息检查和 diff 检查通过；真实模型冒烟
  单独报告，不把服务暂时不可用当作代码通过。

## 技术价值、风险与遗留

将“模型请求候选”和“可执行的完整工具调用”分开，重试只发生在前者阶段；无效写入预览
在审批之前失败，可减少无意义授权。HTTP 层尝试可能增加请求与 Token 消耗，尤其在服务端
已生成但客户端没收到完整消息时；账本不能把缺失 usage 记成零。真实模型冒烟只证明一条
纯问答路径，不能推断复杂编码任务成功率，也不能代替多任务评测。

记录为准，不把尚未发生的推送或合并写成已完成。
