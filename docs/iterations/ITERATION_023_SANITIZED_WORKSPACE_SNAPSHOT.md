## 目标

Task 3.5 在 Docker 挂载之前建立一条独立的输入边界：每条已批准命令都从声明的工作区创建新
快照，只复制经过 `lstat`、directory fd 和 `O_NOFOLLOW` 检查的普通文件。`.git`、`.env*`、
凭据、`.venv`、`runs` 与 `.pi-claw` 只记录相对路径和排除原因，不进入容器输入。

## 实现

| 范围 | 修改 |
|---|---|
| 固定排除规则 | `Workspace.snapshot_exclusion_reason()` 按任意层级名称排除版本库、dotenv、语言/云/容器/Terraform 凭据、虚拟环境、运行产物和会话目录 |
| 无跟随遍历 | 从工作区 root directory fd 开始，逐层使用相对 fd、`lstat` 和 `O_NOFOLLOW` 打开节点 |
| 特殊节点 | symlink、FIFO、设备和其他非普通节点让整个快照失败；即使名称本应排除也不能绕过节点类型检查 |
| 竞态复核 | 打开目录后核对 device/inode；普通文件必须只有一个硬链接；复制前后核对 identity、链接数、类型、大小、mtime 和 ctime |
| 资源预算 | 默认最多 20,000 个文件、128 MiB；超限整体失败，不返回截断快照 |
| 节点预算 | 普通文件、目录和排除项共享最多 40,000 个节点，避免空目录或排除名消耗 inode/manifest 内存 |
| 可审计清单 | manifest 记录普通文件相对路径、大小、SHA256，以及排除项相对路径和原因；manifest 自身不放入 `/input` |
| 生命周期 | 每次命令新建独占快照；正常、异常、取消和超时路径都清理，清理失败显式进入结果或异常元数据 |

## 测试设计

测试先于实现建立，覆盖：

- 普通文件复制、确定性 manifest 摘要和固定排除原因；
- symlink、FIFO、设备文件以及伪装成 `.env` 的特殊节点全部拒绝；
- 文件数、总字节超限整体失败；
- 复制期间修改文件、检查后把父目录替换成外部 symlink 均失败；
- 工作区内普通名称指向外部凭据的硬链接失败；初始化失败和只读半成品也会删除私有快照根；
- 两次命令生成不同快照，命令 cwd 不能缩小或扩大批准的工作区根；
- `uv sync` 在 Docker 后端被拒绝；
- 快照清理异常或中途节点消失不能被吞掉；工具层把受策略约束的工作区根显式传给 Runner。

- 真实 Docker 命令的快照元数据记录普通文件数、总字节和 manifest SHA256；元数据与 daemon

  并删除整棵临时树；构建异常只返回固定摘要，宿主临时路径不会进入 ToolResult/Trace。
