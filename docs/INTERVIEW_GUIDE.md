# 面试演示与讲述指南

## 3 分钟演示顺序

1. 画出 `任务 -> Model -> ToolCall -> Policy -> ToolResult -> Trace` 数据流。
2. 先运行离线 demo，说明为什么不用 API key 也能验收工程层。
3. 展示一次路径越界或危险命令被拒绝，并在 trace 中找到理由。
4. 展示批准前后文件是否改变，以及测试结果。
5. 用 replay 查看历史事件，强调 replay 不会重复副作用。
6. 最后再说明真实模型、Memory、Sandbox、Subagent 是可插拔扩展。

## 面试官可能追问

### 为什么不直接用大型 Agent 框架？

不是因为框架一定不好，而是这个项目的目标是学习和展示 Agent loop、工具协议、权限与评测。
轻量核心让每个边界都能被单独解释和测试；生产项目是否采用框架要根据团队维护成本再决定。

### ScriptedProvider 有什么价值？

它固定了模型变量，能够复现工具和策略缺陷。离线通过只证明工程闭环正确，不证明真实模型效果；
真实模型需要在同一任务集上另测成功率、步骤数、成本和延迟。

### 为什么默认不开放 bash？

自由文本 shell 很难安全验证。首版只允许 argv 和少量命令，并要求审批。未来即使加入容器，
应用层 Policy 仍然保留，因为容器不是业务权限系统。

### 为什么没有一开始就上 Multi-Agent？

多 Agent 会增加上下文同步、冲突和评测变量。先建立单 Agent 基线，再加入 Reviewer 或并行角色，
只有指标提升大于复杂度成本时才保留。

### 项目效果怎么衡量？

至少记录任务成功率、测试通过率、未授权动作率、工具调用数、补丁规模、证据覆盖率、replay
一致性和耗时。不要用一次演示成功代替版本化评测。

## 简历表达模板

> 从零实现轻量本地 Coding Agent，将模型决策与工具执行解耦；设计工作区路径校验、写入审批、
> argv 命令白名单和脱敏 JSONL trace，并以离线 ScriptedProvider 与安全测试建立可重复基线。

只有在对应实现和测试确实存在时再使用这段表述，并把实际测试数量、成功率替换成真实数据。
